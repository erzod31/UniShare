# Problemas conocidos y bloqueos

| ID | Severidad | Estado | Problema | Próxima acción |
|---|---|---|---|---|
| K-001 | Media para Android | Parcial | SDK API 36, emulador y sincronización en teléfono físico están verificados. Faltan recorridos físicos completos de Sharesheet, SAF y TalkBack. | Repetir el checklist de `platforms/android/README.md` en el teléfono. |
| K-002 | Media | Aplazado con empaquetado firmado | Windows usa WPF y el ZIP portátil no tiene identidad de paquete, por lo que no aparece como Share Target nativo. La documentación oficial exige MSIX/sparse package y firma. | Incorporar Windows App SDK/MSIX al cerrar la fase de firma; mientras tanto usar arrastrar/soltar o la extensión local. |
| K-003 | Alta | Abierto | No existe certificado de firma definitivo ni cuentas de tienda. | Usar firma de desarrollo; publicación externa requiere intervención del propietario. |
| K-004 | Media | Resuelto en 0.5.1 | El E2E Android–Windows estaba verificado sólo con AOSP. | El usuario confirmó sincronización real en teléfono por Wi-Fi y datos móviles. Mantener las pruebas de protocolo. |
| K-005 | Media | Resuelto de forma acotada en 0.6.0 | Una captura web fiel no debe conservar scripts ni formularios activos. | La extensión captura texto renderizado y hasta 12 imágenes; Windows valida y genera HTML inerte con CSP. No incorporar SingleFile ni ejecución guardada. |
| K-006 | Media | Resuelto | El MIME se infería por extensión y no por firma del contenido. | Detector acotado de firmas; una firma reconocida prevalece sobre cabecera y extensión. |
| K-007 | Baja | Resuelto | Un fallo de DB posterior a promover un blob puede dejar contenido CAS sin referencia. | Windows y Android eliminan al arrancar sólo blobs canónicos sin referencia con al menos siete días, preservan archivos recientes/desconocidos y tienen pruebas de regresión. |
| K-008 | Media | Abierto | El backup v1 no está cifrado y puede contener datos sensibles. | Añadir cifrado optativo con contraseña y diseño de recuperación; documentar que el ZIP actual debe protegerse. |
| K-009 | Alta | Resuelto | La política de descargas validaba DNS antes de que `HttpClient` resolviera de nuevo. | La conexión usa `ConnectCallback` y el socket se abre directamente contra una IP validada; prueba con hostname `.invalid`. |
| K-010 | Media | Resuelto | H6 descargaba HTML sin una vista de lectura sanitizada. | La captura elimina contenido activo, vuelve a codificar el texto y aplica CSP sin red/scripts; prueba hostil incluida. |
| K-011 | Baja | Parcial en 0.6.0 | La descarga HTTP segura sigue siendo una vista de lectura básica. La extensión ya conserva texto renderizado por JavaScript e imágenes visibles permitidas por canvas, pero puede omitir estructura compleja, imágenes entre orígenes, vídeo y canvas. | Mantener ambos modos; mejorar estructura sólo con fixtures adversariales y sin reactivar contenido. |
| K-012 | Baja | Resuelto de forma conservadora | Android verifica e incorpora respaldos sin borrar datos; las divergencias se conservan como conflictos. No ofrece reemplazo destructivo del perfil. | Mantener la restauración no destructiva; un reemplazo total sólo se añadirá con previsualización y rollback. |
| K-013 | Baja técnica | Aceptado | Android usa `SQLiteOpenHelper` y esquema v5. Las migraciones v1→v5 y el contrato portable están probados. | Migrar a Room sólo si reduce coste real sin cambiar ni perder el esquema existente. |
| K-014 | Media | Resuelto en 0.6.10 | Android contrastaba sólo el MIME declarado por `ContentResolver`. | Una política sin dependencias inspecciona 512 bytes, reconoce las mismas firmas básicas que Windows, conserva contenedores ZIP conocidos y rechaza HTML/SVG o firmas contradictorias antes de promover el blob. Pruebas unitarias y SAF real en API 36 verifican aceptación, rechazo y limpieza. |
| K-015 | Media | Resuelto | La sincronización manual por archivo se eliminó. Windows expone un nodo autenticado sólo en loopback y Android sincroniza directamente mediante Tailscale Serve. | Mantener compatibilidad del protocolo y probar cada migración. |
| K-016 | Baja | Resuelto | Cada alta tiene UUID propio. La retirada replica el tombstone de esa alta observada y nunca elimina una re-alta concurrente con otro UUID. | Mantener la prueba de convergencia y no sustituir esta semántica por comparación de timestamps. |
| K-017 | Media | Limitación de plataforma | Android cerrado no puede recibir siempre al instante sin push cloud o servicio permanente; WorkManager tiene intervalo periódico mínimo de 15 minutos y ejecución inexacta. Un servicio `dataSync` tampoco puede ser permanente en Android 15: está limitado a seis horas por cada 24. | Sincronización inmediata al emparejar, editar y abrir; sondeo activo y trabajo durable en segundo plano. No introducir una nube obligatoria sólo para push. |
| K-018 | Media | Resuelto y verificado en 0.5.1 | Faltaba comprobar el transporte directo fuera de la Wi-Fi doméstica. | El usuario confirmó sincronización funcional desde el teléfono usando datos móviles el 2026-09-26. Sólo queda como prueba de robustez el cambio de red durante una operación en curso. |
| K-019 | Baja para metadatos | Resuelto en 0.6.9 | Después del snapshot inicial, el registro causal selecciona sólo los agregados modificados y los blobs ausentes. El ACK se persiste después de importar la respuesta y los reintentos repiten el mismo delta. | Mantener las regresiones de reenvío y recuperación ante cursor futuro; añadir property tests extensivos durante el endurecimiento. |
| K-020 | Baja | Resuelto en 0.6.10 | La extensión Chromium tenía endpoint y sintaxis verificados, pero faltaba cargarla en un navegador real. | Edge cargó la extensión MV3 con perfil aislado, guardó configuración, abrió el popup sobre una pestaña HTTP real y creó un híbrido offline con título, autor, resumen, colección y CSP verificados en SQLite. |
| K-021 | Alta | Resuelto y verificado en 0.5.1 | Android podía usar el DNS de la red física para una URL `.ts.net` y el encabezado mostraba “Sincronizado” sólo por existir una configuración. | Las conexiones se enlazan a la red VPN; el estado depende del último resultado y los errores explican DNS/túnel dividido. El usuario confirmó la sincronización real en el teléfono afectado el 2026-09-26. |
| K-022 | Alta de usabilidad | Resuelto en 0.6.1 | Los controles desplegables nativos de WPF podían conservar fondo blanco con texto claro en tema oscuro; la eliminación recuperable se llamaba “Archivar” y era difícil de encontrar. | ComboBox, elementos y menús usan superficies/primer plano explícitos y recursos nativos alineados al tema. Windows y Android muestran **Eliminar**, confirmación, Papelera y restauración. Mantener el recorrido visual por tema en futuras versiones. |
| K-023 | Alta de usabilidad | Resuelto en 0.6.2 | La clave de conexión existía sólo dentro del QR/enlace de emparejamiento y no podía copiarse por separado para configurar Edge. | **Conectar dispositivos y Edge** muestra puerto y clave de sólo lectura, con botones de copia independientes y advertencia de privacidad. |
| K-024 | Media de distribución | Preparado; publicación externa pendiente | La instalación estable de Edge no puede hacerse desde un ZIP/CRX local para usuarios particulares: requiere Edge Add-ons. | Paquete, iconos, ficha y privacidad 0.6.4 preparados. Falta que el propietario registre/inicie sesión en Partner Center, publique la política en HTTPS, acepte los términos y envíe a certificación. |
| K-025 | Alta | Resuelto en 0.6.4 | Android sólo comparaba la revisión remota durante el trabajo periódico; una edición local podía quedar pendiente indefinidamente si el servidor no cambiaba. | Cada mutación incrementa una generación local durable. El coordinador sincroniza cuando hay cambios locales y sólo confirma la generación efectivamente transferida. |
| K-026 | Alta | Resuelto en 0.6.4 | Cambiar de biblioteca en Windows podía abrir un perfil inválido y la nueva instancia podía competir con el mutex o el puerto de la anterior. | Se valida integridad/esquema antes de guardar el perfil; la instancia nueva espera la entrega y la anterior detiene el servidor antes de liberar el mutex. |
| K-027 | Media | Resuelto en 0.6.4 | Recrear la actividad Android podía reprocesar `ACTION_SEND`, y trabajos de E/S podían usar la base después de cerrarla. | Los intents consumidos se limpian y el almacén vive en `Application`, no en la actividad. |
| K-028 | Media de usabilidad | Resuelto en 0.6.4 | Guardar sólo un enlace no obtenía metadatos automáticamente y la extensión no los enviaba de forma consistente. | Windows, Android y Chromium extraen título/autor/descripción con límites y política de red; los datos escritos por el usuario no se sobrescriben. |
| K-029 | Media | Resuelto en 0.6.4 | Windows ocultaba silenciosamente los elementos posteriores al 200 y Android cargaba toda la biblioteca con consultas N+1. | Paginación explícita, carga incremental, filtros SQL exactos y lectura agrupada de etiquetas; las colecciones son navegables en ambos clientes. |
| K-030 | Alta de confianza | Resuelto en 0.6.4 | Android podía seguir mostrando «Sincronizado» después de fallar el sondeo y el smoke de Windows podía pasar aunque el servidor directo no iniciara. | El fallo cambia el estado visible a pendiente y el smoke devuelve error si el servidor no queda operativo. |
| K-031 | Media | Resuelto en 0.6.4 | Una búsqueda Android lenta podía sobrescribir una consulta más reciente. | Cada refresco tiene una generación; sólo la solicitud más nueva puede publicar resultados en la interfaz. |
| K-032 | Alta de confianza | Resuelto en 0.6.5 | Windows podía publicar una búsqueda obsoleta después de otra más reciente o iniciar dos páginas con el mismo desplazamiento. | Generación monotónica, coalescencia de paginación y dos pruebas de regresión. |
| K-033 | Baja técnica | Aceptado temporalmente | AGP 8.13 emite un aviso por metadatos SDK XML v4. Las bibliotecas Android que lo eliminan exigen API 37/AGP 9.1, todavía no disponibles en el SDK estable del host. | Mantener la última combinación con metadatos AAR compatibles con API 36; migrar API/AGP/Kotlin juntos cuando API 37 esté disponible. |
| K-034 | Alta de confianza | Resuelto en 0.6.6 | Tras recuperarse de un fallo temporal, Android podía comprobar que las revisiones coincidían pero conservar el resultado anterior «Sincronización pendiente». Los reintentos inmediatos también podían encadenarse detrás de un trabajo antiguo en espera. | Una comprobación remota coincidente y sin cambios locales confirma explícitamente «correcto (sin cambios)» y limpia el aviso. Cada reintento inmediato reemplaza el anterior en vez de quedar detrás de él. |
| K-035 | Media de usabilidad | Resuelto en 0.6.7 | Los enlaces antiguos podían conservar sólo el dominio como título y la descripción existía en detalles pero no se veía en la biblioteca. | Windows y Android priorizan Open Graph, Twitter Cards y HTML estándar; muestran la descripción en la tarjeta y ejecutan una migración de enriquecimiento una vez, con reintento manual y sin sobrescribir campos editados. |
| K-036 | Alta de calidad | Resuelto en 0.6.8 | La descripción automática de 0.6.7 procedía de `meta description`/Open Graph y podía ser publicidad o texto genérico no representativo del elemento guardado. | El resumen se extrae literalmente de `articleBody`, `<article>` o `<main>`, elimina regiones ajenas y enlaces densos, nunca usa la descripción promocional como sustituto, y migra los valores automáticos anteriores conservando notas distintas. |
| K-037 | Alta de confianza | Resuelto en 0.6.11 | Al salir completamente, WPF cerraba la ventana pero podía bloquear el hilo UI esperando de forma síncrona la detención del servidor directo; el proceso seguía vivo más de 60 segundos. | El apagado espera el servidor de forma asíncrona y después ejecuta `Shutdown`. El empaquetado prueba el EXE real y exige salida 0 en un perfil temporal. |
| K-038 | Media de funcionalidad | Resuelto en 0.6.12 | F-11 exigía selección múltiple, pero Windows y Android sólo exponían acciones sobre un elemento. | Windows usa selección extendida y acciones por lote; Android ofrece modo Seleccionar, casillas, seleccionar todo y actualización transaccional. Mantener pruebas de conteo/partición y recorrido de emulador. |
| K-039 | Alta de calidad | Resuelto en 0.6.13 | Las páginas de YouTube sin párrafos semánticos activaban el fallback de cuerpo completo; al retirar etiquetas, su pie de navegación quedaba concatenado como resumen. La migración anterior lo protegía erróneamente como una nota manual. | Se prioriza la descripción original del vídeo, se analiza por líneas, se prohíbe el fallback indiscriminado de `<body>` y se reconoce únicamente la firma compacta del menú defectuoso para actualizar datos históricos sin tocar notas. Cinco de cinco enlaces reales afectados produjeron resumen directo y cero navegación. |
| K-040 | Media de robustez | Resuelto en 0.6.16 | Un fallo al preparar `staging` después de adquirir el bloqueo de sincronización podía dejar bloqueadas las solicitudes siguientes hasta reiniciar Windows. | La adquisición queda protegida por `finally`; una regresión provoca el fallo dos veces y demuestra que la segunda petición termina en vez de esperar al bloqueo abandonado. |
| K-041 | Baja de localización | Resuelto en 0.6.16 | Varios resultados dinámicos de descargas, conflictos y flujos normales de Android permanecían en español al elegir inglés. | Se localizaron los estados detectados y se añadieron regresiones para mensajes dinámicos, preservando texto desconocido del usuario. |
| K-042 | Alta de instalación | Resuelto en 0.6.16 | El agente de bandeja interpretaba la petición de cierre de Windows Restart Manager como un cierre ordinario y ocultaba la ventana; una actualización podía terminar con archivos bloqueados. | `App.OnSessionEnding` marca el cierre como explícito y permite finalizar servidor y recursos antes de que el instalador sustituya los binarios. La actualización sobre una instancia activa se verifica con el instalador final. |
