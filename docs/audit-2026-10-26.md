# Metadatos, títulos y traducción local — auditoría 2026-10-26

Fecha: 2026-10-26. Alcance: extracción de metadatos en Windows, Android y Chromium. No es una nueva
declaración de cierre de todos los requisitos del proyecto.

## Ampliación 0.6.23: traducción automática integrada

La petición posterior sustituye el lanzador Google por traducción automática de descripciones dentro
de UniShare al idioma elegido en Ajustes. Se revisaron las vistas de biblioteca/edición, preferencias,
almacenamiento y empaquetado en ambas plataformas antes de modificar el código.

- Un único núcleo JS/WASM Bergamot de Mozilla, sin servidor ni API de traducción. El código C#/Kotlin
  sólo integra la vista nativa, caché y descarga de modelos. WebView2 SDK estable 1.0.4314.35 en Windows;
  WebView del sistema en Android. No se distribuye otro runtime nativo de inferencia.
- WASM oficial 4.0/v0.6.0 y glue coincidentes de Firefox 144; fuente del motor
  `mozilla/translations@1de4a085d3a7afb625c51a60aabb5ad298e4059f`. Manifest de procedencia y hashes
  en `shared/translation/vendor/provenance.json`; modelos estables 3.0 fijados en `models.json`.
- Descargas por necesidad, hash/tamaño antes de promoción y hash/tamaño tras descomprimir. El host
  sólo acepta hashes del catálogo y un CDN público fijo. Ninguna descripción, URL del elemento o
  credencial aparece en las peticiones. Worker separado para no bloquear la interfaz.
- Traducciones derivadas por texto/idioma/versión; originales y títulos no se modifican ni sincronizan
  como traducciones. Botón original, editor explícito del original y ajuste persistente para desactivar.
- Se retiraron el constructor de URL Google y sus textos/pruebas de ese flujo sustituido. Los nuevos
  tests verifican caché, errores, original, preferencias y motor real; las comprobaciones de edición
  en lectura y enlaces clickeables se conservan con el componente nuevo.
- La primera prueba nativa Android falló por crear una vista de prueba sin conectarla a la ventana.
  Se corrigió el ciclo de vida del harness y el motor tradujo realmente. Se conserva el informe fallido.
- La prueba de cambiar idioma encontró una falla real: `UiStrings.current` no era observable y Compose
  podía conservar la navegación española tras elegir inglés. Se convirtió en estado observable y se
  calcula la etiqueta accesible en composición; la prueba exige navegar en el idioma nuevo.

Validación actual: 189 .NET, 122 JVM y 47 Node pasan. Windows infiere seis casos con/sin red y verifica
vista/original/preferencia/cancelación. Una prueba Edge de 3169 caracteres conserva las 35 frases,
el final, saltos y tokens literales. La validación final de dispositivo y entrega se detalla en
[la matriz](verification.md). Los registros originales fallidos y finales se preservan bajo artifacts.

API 37 pasa 2/2 de traducción/lectura/idioma y seis inferencias reales online/offline, 22/22 de núcleo
normal y 22/22 al 200 %. La ausencia de WebView se ensayó deshabilitando/restaurando el proveedor sólo
en el emulador propio: original, edición, preferencias y recreación pasan 1/1. El host es opcional;
su ausencia no impide usar la biblioteca. Una expectativa del harness usaba `Modify summary`; se
corrigió a la etiqueta real ya existente `Edit summary`, manteniendo las aserciones de edición.

La entrega R8 real también se instaló y actualizó en API 37. Se restauraron dos elementos sintéticos
mediante SAF; el APK mostró `My publication from mobile`, `Edited summary` y la acción de original,
conservando enlaces/emoji/hashtag. Se completó un texto largo de confirmación que aún aparecía en
español al elegir inglés. El paquete final verifica esa confirmación y conserva los dos elementos
después de actualizar y arrancar en frío.

Windows final instalado con salida 0: 25 elementos, seis tablas y clave de emparejamiento idénticas;
EXE igual al publicado y nodo autenticado activo. Backups antes/después y después de leer inspeccionados.
La lectura real generó seis vistas del mismo idioma sin modificar ninguna tabla. El E2E final 1/1
comprueba descripciones originales/autor, archivos, ACK y reparación en ambos sentidos.

El paquete público rechazó el HOME virtual que Emscripten incorpora en su glue upstream. El escáner
reconoce únicamente los bytes con SHA-256 revisado y retira ese literal sólo de la comprobación de ruta
Linux; las demás reglas siguen aplicándose. Un repositorio fixture con el mismo archivo y atributos LF
se acepta; al modificarlo con una ruta sintética privada se rechaza. El motor upstream queda intacto.
Los hashes/paquetes finales, pruebas y límites están registrados en la matriz y en el manifiesto SHA-256.

Límites: los pares necesitan modelos la primera vez; no se han ensayado todos los idiomas del catálogo,
Android 8 ni hardware físico/lectores de pantalla. Detección de textos muy cortos o mezclados y calidad
de traducción pueden fallar; el original siempre se conserva. No se añade traducción de títulos, un
servidor, proveedor de pago ni envío de texto. La búsqueda/exportación siguen usando el original.
El endurecimiento de seguridad y las pruebas de hardware ya pendientes no se declaran completados.

## Diagnóstico e investigación

1. El extractor previo buscaba párrafos y JSON-LD, pero TikTok publica el pie en sus datos de
   hidratación. No había adaptador para ellos.
2. La misma publicación pública entrega `webapp.video-detail.itemInfo.itemStruct` al agente Windows
   y `webapp.reflow.video.detail.itemInfo.itemStruct` al agente Android. La comprobación de Internet
   en Android falló inicialmente por no contemplar la segunda ruta. No se cambió el agente para
   fingir otro cliente: se añadió la estructura móvil real.
3. El filtro de artículos exigía prosa y longitud mínima y rechazaba texto igual al título. No sirve
   para un pie original de una publicación que puede consistir en hashtags, emojis o pocas palabras.
4. Android usaba regex para JSON-LD, pudiendo asociar el tipo de un objeto con la descripción de otro.
   Windows y Chromium tampoco vinculaban suficientemente una recomendación a su propia URL.
5. Se compararon la página pública, oEmbed y Player oficiales. El primero contiene el pie; las rutas
   alternativas de embed devolvieron 429 o datos sin descripción. La documentación de TikTok anuncia
   la transición al Player y muestra un oEmbed que puede carecer de título. Basar todo en ese endpoint
   sería una dependencia frágil. Fuentes y decisión: [ADR 0030](decisions/0030-pies-originales-y-variantes-tiktok.md).

## Resultado implementado

- TikTok actual desktop/móvil y legacy: pie y autor del ID exacto, después de redirecciones válidas.
  Se ignoran `shareMeta`, challenges, música y recomendaciones como fuentes del pie del post.
- Textos multimedia/sociales literales, con saltos y URLs, hasta 4000 puntos de código; títulos hasta
  500 unidades UTF-16 sin romper emojis. Un pie vacío identificado no provoca búsquedas innecesarias.
- JSON-LD con objetos/tipos reales, identidad y control de ambigüedad. Artículos conservan extracción
  de prosa; los demás posts admiten sus pies breves.
- oEmbed opcional del mismo proveedor, sin reenviar consulta/fragmento del enlace. Respuestas sin
  título y errores no inventan resúmenes ni descartan metadatos principales. No hay nuevas dependencias
  runtime, cookies, credenciales, servicio externo obligatorio ni resolución de desafíos.
- Reconsulta v4 de enlaces existentes y acción manual **Actualizar títulos y resúmenes**. Las notas
  manuales se conservan según las reglas existentes. No se altera SQLite, backups ni protocolo sync.

## Límites honestos

- La migración v4 se ejecutó realmente desde la aplicación instalada sobre los 16 TikTok anteriores de
  la biblioteca Windows. Se compararon backups previos/posteriores sin registrar URLs, títulos ni pies
  personales. La recepción de esos cambios en el teléfono físico continúa **NO VERIFICADA** en esta
  entrega; la sincronización de los mismos campos sí se ejecutó entre emulador y nodo Windows real.
- Posts privados, borrados, regionalmente restringidos, desafíos de acceso o cambios futuros del HTML
  pueden impedir obtener la descripción. El enlace permanece guardado y el campo queda vacío.
- La reconsulta automática se intenta al abrir; no es un rastreador permanente. Si un sitio falla o
  vuelve a estar disponible, la acción de actualización permite reintentar. No se reemplazan notas
  manuales arbitrarias para intentar adivinar si eran metadatos defectuosos.
- No se afirma compatibilidad con todas las redes sociales ni descarga del vídeo TikTok; esta corrección
  obtiene sus metadatos. La copia offline sigue siendo una instantánea estática de página.
- Se conserva Gradle fijado y compatible; el aviso de patch disponible y las deprecaciones comunicadas
  por Gradle no se silencian. Actualizar la cadena completa es una tarea independiente.
- Certificados/tiendas y pruebas físicas/de accesibilidad pendientes siguen identificados en
  [known-issues.md](known-issues.md); el endurecimiento adicional continúa aplazado por el usuario.

## Continuación 0.6.21: títulos y traducción

- Los 16 títulos anteriores eran exactamente `TikTok - Make Your Day`. El primer ajuste v5 no
  reconocía esa etiqueta; la comprobación del perfil lo detectó y se añadió una regresión. La v6 final
  la compara con el título publicado y ahora usa el título específico del post o su primera línea.
  `headline`/`name` JSON-LD también se usan en el campo título, con la misma política de identidad.
- Se verificaron realmente los 16 cambios. Los 25 UUID/URLs, todas las descripciones, los demás títulos
  y las cinco tablas portables de organización/assets quedaron idénticos. Se conserva backup validado.
- Windows y Android ofrecen traducción voluntaria en el navegador con Google Translate. Confirmación,
  destino español/inglés según interfaz y copia completa explícita para textos demasiado largos.
  El original no se sustituye. No se incorpora un motor offline ni se añade un servicio obligatorio.
- Pruebas: 179/179 .NET, 113/113 JVM, 36/36 Node, 37/37 contratos Edge, 22/22 instrumentadas normales
  y al 200 %. El caso Android comprueba cancelar sin lanzar proveedor y confirmar en ambos idiomas,
  interceptando el Intent para evitar envío de texto. El sitio Google se probó aparte con texto sintético.
- Internet: Android recuperó el hash esperado del TikTok público; Windows recuperó metadatos de un enlace
  existente y pudo corregir sus títulos. El último acceso al ejemplo público desde Edge fue denegado
  por TikTok y la sonda Windows de ese ejemplo tampoco obtuvo pie. Se conserva el fallo como evidencia
  de una limitación del proveedor. No se cambian agentes, cookies ni se resuelven desafíos para sortearlo.
- Instaladores, APK y paquetes reconstruidos desde `7ba5989e17ec264d002a25e758f0332766cf0a21`.
  Windows actualizado y APK instalado/arrancado en emulador API 37, firma histórica intacta. E2E con el
  ejecutable final 1/1, incluidos pie con enlaces/emojis, autor, archivos, ACK y reparación.

Uso y límites: [ADR 0031](decisions/0031-titulos-y-traduccion-voluntaria.md),
[privacidad](PRIVACY.md) y [evidencia final](verification.md).

## Continuación 0.6.22: longitud de los títulos

La revisión del usuario detectó que los 16 títulos ya identificaban contenido, pero seguían copiando
hasta 500 caracteres del pie. Se confirmó que los 16 coincidían exactamente con la alternativa antigua.
Ahora, cuando no existe un título específico, se usa un encabezado de hasta 80 caracteres Unicode,
con límite de palabra y elipsis cuando es necesario. Las listas finales de etiquetas/URLs permanecen
en la descripción; un hashtag temático único se conserva. Los títulos personalizados no coincidentes
con la alternativa antigua permanecen intactos. La descripción no se acorta para producir el título.

La migración v7 se ejecutó realmente desde la aplicación instalada: **16 títulos acortados, máximo 79**.
Comparando backups: mismas 25 identidades/URLs, todas las descripciones, los demás títulos y las otras
cinco tablas portables. Pruebas: 184 .NET, 118 JVM, 41 Node, 42 Edge y 22 instrumentadas normales/200 %,
todas correctas. Una corrida UI quedó tapada por el ANR del proceso Android `com.android.systemui`;
se conservó XML/captura, se reinició el entorno y se repitieron íntegramente ambas suites. No se redujeron
requisitos ni se excluyeron pruebas. El E2E final y el APK release instalado también son correctos.

Política de títulos: [ADR 0032](decisions/0032-encabezados-tiktok-breves.md).
