# Auditoría integral de UniShare — 2026-10-05

## Resultado ejecutivo

La base 0.6.4 era funcional y no tenía fallos de compilación ni pruebas rotas. La auditoría no encontró
un error crítico conocido, secretos incorporados al repositorio ni paquetes NuGet con avisos de
vulnerabilidad. Sí encontró un fallo de concurrencia visible en Windows, dependencias y documentación
desfasadas, duplicación de versiones NuGet y una automatización CI anterior al toolchain actual.

La entrega 0.6.5 corrige esos puntos sin reescribir el dominio, cambiar el formato de datos ni ampliar
la fase de seguridad que el propietario decidió aplazar.

## Alcance inspeccionado

- 192 archivos versionables, solución .NET, aplicación WPF, módulo Android, extensión MV3,
  empaquetado, documentación, migraciones y 74 pruebas iniciales.
- Compilación, formato, análisis integrado, restauración bloqueada, pruebas, cobertura, lint Android,
  ensamblado release, publicación Windows, smoke test, benchmark FTS5 y scripts de distribución.
- Estado Git y cambios previos, grafo NuGet directo/transitivo, paquetes vulnerables/obsoletos,
  versiones estables Android y acciones CI.
- Búsqueda de código abandonado (`TODO`, `FIXME`, `HACK`), secretos obvios y configuraciones peligrosas.

## Hallazgos y correcciones

| ID | Severidad | Hallazgo | Corrección / estado |
|---|---|---|---|
| A-001 | Alta | Dos búsquedas Windows podían terminar fuera de orden y la antigua reemplazar a la nueva. | Corregido con generación monotónica; una respuesta obsoleta ya no publica resultados. Prueba de regresión añadida. |
| A-002 | Media | Varias pulsaciones de “cargar más” podían iniciar lecturas concurrentes con el mismo desplazamiento. | Corregido mediante coalescencia de carga y validación de generación/desplazamiento. Prueba de regresión añadida. |
| A-003 | Media | Versiones NuGet repetidas en cada proyecto y xUnit 2 marcado como legado. | `Directory.Packages.props`, xUnit v3 4.0.1, runner 4.0.0 y Microsoft.Testing.Platform. |
| A-004 | Media | SDK .NET, SQLite y bibliotecas Android tenían parches estables posteriores. | .NET SDK 10.0.401, SQLite 10.0.12, Compose BOM 2026.06.01, Activity 1.13.0 y Core 1.18.0. |
| A-005 | Media | CI usaba acciones antiguas, una acción Gradle adicional y llamaba “framework-dependent” a un binario autocontenido. | Acciones oficiales actuales, caché Gradle en `setup-java`, cobertura MTP, concurrencia cancelable y nombre corregido. |

## Arquitectura

La separación `Domain → Application → Infrastructure/Desktop` sigue siendo adecuada. Persistencia,
blobs, backup, sincronización y captura están tras interfaces o servicios explícitos; Android conserva
su implementación local compatible con el contrato portable. No hay un servidor cloud obligatorio.

La centralización de paquetes elimina una fuente de divergencia sin acoplar capas. La modernización de
pruebas reemplaza VSTest/xUnit 2 por Microsoft.Testing.Platform/xUnit v3 y deja la cobertura como parte
del pipeline normal. Se evitó una migración estética de los tres archivos grandes: deben extraerse por
casos de uso cuando se añada comportamiento y con pruebas que protejan cada frontera.

## Rendimiento y cobertura

- Benchmark: 100 000 elementos, 30 consultas, mediana 56,1519 ms, p95 63,681 ms; umbral 300 ms.
- Dominio: 67,91 % de líneas y 72,73 % de ramas en su módulo dedicado.
- Aplicación/dominio/infraestructura: 90,22 % de líneas y 70,75 % de ramas en pruebas de infraestructura.
- Escritorio/aplicación/dominio: 9,67 % de líneas; la UI sigue dependiendo en gran medida de smoke y
  recorridos manuales. Las dos nuevas pruebas cubren las carreras de refresco y paginación.

La cobertura es evidencia orientativa, no un criterio aislado de calidad. No se impuso un umbral global
porque mezclar XAML/eventos visuales con el núcleo probado produciría una métrica engañosa.

## Dependencias y herramientas

- NuGet: sin paquetes vulnerables, obsoletos ni actualizaciones pendientes tras la migración.
- Android: 36 pruebas debug y 36 release, lint release y R8/ensamblado correctos con las versiones nuevas.
- Wrapper Gradle conserva SHA-256; Kotlin 2.3.21 y WorkManager 2.12.0 ya estaban al día.
- CI deja de depender de `gradle/actions/setup-gradle`; no fue necesario aceptar términos nuevos.

## Pendientes honestos

- Seguridad aplazada por decisión del propietario: firma comercial, cifrado opcional de backup,
  SBOM/fuzzing especializado y auditoría externa. La validación MIME funcional de Android se cerró en 0.6.10.
- Requieren acceso o hardware externo: publicación Edge Add-ons, MSIX/Share Target firmado y recorridos
  completos con TalkBack, Sharesheet y SAF en un teléfono.
- La optimización de delta de operaciones y ACK causal se cerró en 0.6.9; después del snapshot inicial
  sólo se intercambian agregados modificados y blobs ausentes.
